Universal Multi-Cloud Migration & Data Framework

One parameter-driven framework · any source → any target · multi-cloud + on-prem · design blueprint (not code)

Reconciliation (R) and Logging (L) always run and cannot be switched off. A single step can be run alone, a full flow can be run, or a whole dependency graph (DAG) — one table's failure stops only its own downstream; the rest continue. No question is ever asked at run time — every decision is already in the config.

5 · Data types & schema — exact first, never silent

EXACT-FIRST Type mapping

  • Precision, scale, length, nullable read from source metadata and mapped exactly.
  • UI preview shows every column: source type → target type, p, s, length.
  • Deviation only when physically impossible (decimal>38, nanosecond ts, no type info in CSV, unknown type).

ON ISSUE Fail → show → you decide

  • Unmappable column → that table fails (never partial), others continue.
  • Shown clearly: column, source type, target limit, actual max value, affected rows, sample.
  • You decide in UI (data_type_handling): keep length X / cast to string / decimal(38,s).
  • Decision saved in config → never asked again.

SCHEMA MODE per table

  • FIXED — contract; mismatch fails.
  • OVERWRITE — target mirrors source; column-drop needs threshold + approval.
  • EVOLVE — additive (default, safe).
  • STRICT — name/type/order must match.

RECON catches the loss

  • Schema recon (before load): precision ≥, scale ≥, length ≥.
  • Data recon (after stage): count · numeric sum (exact for decimal/int) · null count · max length · min/max · optional hash.
  • Tolerance: decimal/int/count = 0; float = small, client-set.
  • Fail → watermark holds, next step stops, alert sent.

6 · Production guarantees

No partial data Atomic (all-or-nothing) commit via Delta/Iceberg ACID; crash leaves target unchanged.
No bad data in target Stage → recon gate → commit only on pass.
No silent corruption Any deviation fails + highlights + logs + alerts.
No question at run time All decisions pre-set in config; run is unattended.
No unnecessary runs Incremental by default · no-change skip · idempotent · already-success skip.
Scale-ready Chunking · checkpoint-resume · file-sizing · partition pruning · sampling recon (100 TB).
Restart & rollback Resume from failed step; Delta restore / Iceberg snapshot rollback.
Full audit Every file, table, error, rejected row logged; crash-safe, append-only.

7 · Security & deployment — data safe, code safe

DATA stays at client

  • Data never leaves the client platform. No telemetry.
  • Logs hold counts/metadata, not values; errors masked.
  • Reject rows stay in client storage, restricted.
  • Config also lives at the client (version + audit + rollback in control tables).

CODE stays with you

  • Source only in your private repo.
  • Client gets a compiled / obfuscated wheel from a private feed — not downloadable source.
  • License / expiry check (offline key for air-gapped).
  • Honest: ~90% protection — code runs at client, so not absolute.

SECRETS & ROLES

  • Identity-first (IAM/SP/MI/Kerberos).
  • When unavoidable: secret in client vault, referenced by name only — never typed, never in JSON.
  • Roles: Admin · Developer · Operator · Viewer · Approver.
  • Prod writes as service principal; prod changes need approval.
Deployment path: your private repo → build → versioned wheel in private feed → installed in the client notebook. UI (in the notebook) writes the JSON config to the client control store → "Run" / schedule triggers a platform job → run status, recon and errors flow to client-side log tables → UI reads and shows them. Nothing leaves the client; your source is never shipped.
